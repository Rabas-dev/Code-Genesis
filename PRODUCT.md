# Product

## Register

product

## Users

Developers, students, and small teams who want to go from a natural-language idea to a reviewed, runnable full-stack web application without leaving the browser. They are technical users comfortable with code editors and terminals, but tired of the scaffolding and context-switching tax. They work across dark and light environments; the IDE must feel at home in both.

## Product Purpose

Code Genesis turns a single prompt into a complete Next.js / TypeScript project through a staged AI pipeline (requirements, architecture, wireframe, code generation), then delivers it into an integrated in-browser IDE with a Monaco editor, live preview, node-pty terminal, AI quality review, auto-fix self-healing, automated browser testing, GitHub push, and document export. Success means: a developer can go from idea to a reviewed, published project in minutes inside one tab.

## Brand Personality

Precise. Capable. Quietly confident.

The brand does not shout. It communicates through density, craft, and competence. It feels like the tool of someone who knows what they are doing — not a toy, not a demo. The violet accent is the single moment of personality in an otherwise controlled palette.

## Anti-references

- Colorful "AI product" landing pages (loud gradients, hero metrics, glassmorphism everywhere)
- Playful no-code tools (rounded-everything, pastels, hand-drawn illustrations)
- Generic SaaS dashboards (cream backgrounds, eyebrow labels on every section, identical icon-card grids)
- Dark-for-dark's-sake terminal cosplay with neon green on black

## Design Principles

1. **The editor is the product.** Every chrome element — nav, sidebar, panels — exists to serve the code and the output, never to compete with them. Reduce visual noise; let content breathe.
2. **Both modes are first-class.** Dark is the default for developers; light is not an afterthought. The palette must read as intentional and polished in either mode.
3. **Violet is earned.** The brand accent appears on primary actions, active states, and key highlights only. It does not decorate.
4. **Density without crowding.** Developer tools carry a lot of information. Tight spacing is correct; cramped spacing is not. Every element has room to be read.
5. **Motion serves state changes, not decoration.** Transitions indicate something happened. Looping animations that carry no information should be absent or minimal.

## Accessibility & Inclusion

WCAG AA as the minimum. Body text contrast ≥ 4.5:1 in both modes. Muted/secondary text ≥ 3:1. All interactive elements have visible focus rings. Reduced-motion alternative for every animation.
